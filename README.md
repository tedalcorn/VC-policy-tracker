# Vital City coverage tracker

Dashboard and data pipeline for Vital City editorial work — articles, authors, domains, and policy recommendations.

## To run

```bash
python update.py --no-fetch    # rebuild from cached Ghost data
python update.py               # refetch from Ghost + rebuild
cd docs && python -m http.server 8000   # serve dashboard at http://localhost:8000
```

To rebuild the editor-facing policy brief (separate from the regular pipeline because it's not always wanted on every refresh):

```bash
python scripts/build_policy_brief.py
```

To re-run the AI policy-ask scorer (charges your Anthropic API account; ~$1.40 for all 700 articles, but resumable so additive runs only cost the delta):

```bash
python scripts/score_policy_asks.py             # full run
python scripts/score_policy_asks.py --limit 20  # sample
```

## Layout

```
vital-city/
├── update.py               Orchestrator (fetch → build_articles → sync_policy_tracking → build_site)
├── policy_tracking.csv     YOUR MAIN EDITING SURFACE. One row per article. Edit by hand to record
│                           policy recommendations, agencies targeted, action status, etc.
├── config/                 Tunable configs read by the build pipeline.
│   ├── tag_bucket_map.csv      Ghost tag → domain bucket
│   ├── agency_patterns.csv     Regex patterns for detecting agency mentions in body text
│   ├── article_types.csv       Slug-keyed overrides for article_type (event, interview, etc.)
│   ├── byline_aliases.csv      Maps institutional bylines (e.g. "Vital City") to "No byline"
│   └── manual_author_overrides.csv   Author-research profession/employer overrides
├── data/
│   ├── raw/                Ghost API dumps (input)
│   └── processed/          Derived from raw — articles.json, policy_scores.csv, etc.
├── scripts/                Active build pipeline.
│   ├── fetch.py                Ghost API → data/raw/
│   ├── build_articles.py       raw posts → articles.json + agency scan
│   ├── sync_policy_tracking.py  Idempotently adds new article slugs to policy_tracking.csv
│   ├── build_site.py           Bundles everything into docs/data/
│   ├── build_author_research.py  Standalone: profession/employer research from Ghost bios
│   ├── score_policy_asks.py    Standalone: AI-assigned 0–5 policy-ask scores
│   └── build_policy_brief.py   Standalone: editor-facing markdown brief
├── docs/                   The local dashboard. Static HTML + JS.
│   ├── index.html
│   └── data/               Bundled data the dashboard reads (regenerated by build_site.py)
└── projects/               Dated outputs / deliverables NOT served from the dashboard.
    ├── 2026-04-job-application-exercise/   Pre-hire writing exercises (archive)
    ├── 2026-04-09-initial-audit/           Initial audit + taxonomy notes + topic shares
    ├── 2026-04-10-author-research/         Author backgrounds research outputs
    └── 2026-05-19-policy-asks-brief/       Editor-facing brief of high-confidence policy asks
```

## Going forward

- **Scripts in `scripts/`**: only the regular pipeline + standalones called by the user. Anything project-specific should live in `projects/<date>-<purpose>/scripts/` instead.
- **Outputs in `projects/`**: any dated artifact intended for sharing or reference (a brief, an analysis snapshot, a memo) goes in its own dated folder there, not at root.
- **Data in `data/`**: raw inputs and derived outputs of the build pipeline.
- **The site in `docs/`**: only files the dashboard needs to function. Anything else doesn't belong there.
